# Campus Find - Python API (FastAPI)

Base URL in development: `http://127.0.0.1:8000` (Windows app), `http://10.0.2.2:8000` (Android emulator), `http://<your-PC-LAN-IP>:8000` (real phone).
Interactive docs generated by FastAPI: `http://127.0.0.1:8000/docs`.

JSON field names are `snake_case` here (Firestore documents use `camelCase`; the Flutter `BackendApiService` converts between the two).

## 1. Common rules

**Authentication.** Every endpoint except `GET /health` needs the header
`Authorization: Bearer <Firebase ID token>`.
The service verifies the token with the Firebase Admin SDK. Endpoints under `/admin` additionally require the token claim `admin: true`.

**Errors.** Every error has the same shape:

```json
{ "error": { "code": "report_not_found", "message": "No report with that id.", "details": null } }
```

| HTTP | Meaning | Typical `code` |
|---|---|---|
| 400 | Malformed request | `bad_request` |
| 401 | Missing, expired or invalid token | `unauthenticated` |
| 403 | Signed in but not allowed | `forbidden`, `admin_required` |
| 404 | Not found | `report_not_found`, `claim_not_found` |
| 409 | Conflict with the current state | `already_returned`, `report_not_active`, `state_mismatch` |
| 422 | Input failed validation (`details` lists the problems) | `validation_error` |
| 503 | Firebase/Firestore unreachable (the app shows "try again later") | `backend_unavailable` |
| 500 | Unexpected server error (details are logged, never sent) | `internal_error` |

**Report object** (returned by several endpoints; never contains phone or e-mail):

```json
{
  "id": "k3J9...", "type": "found", "user_id": "uid123", "reporter_name": "Asha K",
  "item_name": "Black leather wallet", "category": "Wallets & Purses",
  "description": "Contains a bus pass", "additional_details": "",
  "location": "Library", "location_detail": "2nd floor reading hall",
  "event_at": "2026-10-06T10:30:00Z", "image_url": "https://...",
  "status": "active", "hidden": false, "match_status": "done",
  "match_count": 1, "best_match_score": 87,
  "created_at": "2026-10-06T10:41:12Z", "updated_at": "2026-10-06T10:41:15Z",
  "returned_at": null, "returned_to": null
}
```

## 2. Endpoints

### `GET /health`
* **Auth:** none. **Purpose:** is the service alive? Add `?deep=true` to also test Firestore.
* **200:** `{ "status": "ok", "service": "campus-find-matching", "version": "1.0.0", "time": "2026-10-07T04:00:00Z" }`
  With `deep=true`: adds `"firestore": "ok"`. If Firestore is unreachable: **503** with `"firestore": "unavailable"`.

### `POST /match`  (replaces the CLI's search + matching)
* **Auth:** Bearer; caller must own the report or be an admin.
* **Purpose:** find matches for one report, store them, notify people. Candidates are active, visible reports of the opposite type that belong to OTHER people. Safe to call again (retry): match IDs are deterministic, notifications are not duplicated.
* **Request:** `{ "report_id": "k3J9..." }`
* **200:**

```json
{
  "report_id": "k3J9...",
  "match": true,
  "score": 87,
  "matched_report_id": "abc123",
  "matches": [
    {
      "match_id": "k3J9..._abc123",
      "matched_report_id": "abc123",
      "score": 87,
      "strong": true,
      "breakdown": { "name": 92, "location": 100, "category": 100, "description": 61, "time": 88 }
    }
  ],
  "evaluated": 14,
  "created": 1,
  "updated": 0,
  "notified": 2
}
```
`match`, `score` and `matched_report_id` describe the best match (`false`, `0`, `null` when there is none). `matches` lists all of them, best first.
* **Errors:** 403 not your report; 404 `report_not_found`; 409 `report_not_active` (claimed/returned/hidden reports are not matched); 503.

### `POST /match/score`
* **Auth:** any signed-in user. **Purpose:** score two reports without touching Firestore (used by tests and the "why did these match?" screen).
* **Request:**

```json
{
  "a": { "type": "lost",  "item_name": "iPhone 13", "category": "Electronics", "description": "blue case", "location": "Library", "location_detail": "", "event_at": "2026-10-06T09:00:00Z" },
  "b": { "type": "found", "item_name": "Apple iPhone", "category": "Electronics", "description": "blue cover", "location": "Library", "location_detail": "", "event_at": "2026-10-06T11:00:00Z" }
}
```
* **200:** `{ "score": 87, "match": true, "strong": true, "breakdown": { ... }, "weights": { "name": 0.35, "location": 0.25, "category": 0.15, "description": 0.15, "time": 0.10 } }`
* **Errors:** 422 if both reports have the same `type`, a field is missing, or a date is invalid.

### `POST /reports`  (CLI `add_item`)
* **Auth:** Bearer. **Purpose:** create a report through the API (the app normally writes Firestore directly; this endpoint serves other clients and tests). Stores `reports/{id}` and `private/contact`, builds `keywords`, then runs matching.
* **Request:**

```json
{
  "type": "lost", "item_name": "Black leather wallet", "category": "Wallets & Purses",
  "description": "Brown stitching, college ID inside", "additional_details": "",
  "location": "Canteen", "location_detail": "", "event_at": "2026-10-06T08:15:00Z",
  "image_url": "", "image_path": "", "contact_phone": "9876543210"
}
```
`contact_phone` is optional (defaults to the phone in the user's profile). The e-mail comes from the token.
* **201:** `{ "report": { ...Report object... }, "matching": { ...same shape as POST /match... } }`
* **Errors:** 422 validation (same limits as the security rules); 503.

### `GET /reports`  (CLI `display_items`)
* **Auth:** Bearer. **Purpose:** list visible reports, newest first.
* **Query:** `type` (`lost`/`found`), `status`, `category`, `location`, `limit` (1-100, default 20), `cursor` (the `next_cursor` of the previous page). Admins may add `include_hidden=true`.
* **200:** `{ "items": [ Report, ... ], "next_cursor": "k3J9..." }` (`next_cursor` is `null` on the last page)

### `GET /reports/search`  (CLI `search_item`)
* **Auth:** Bearer. **Purpose:** keyword search ranked by relevance.
* **Query:** `q` (required, 2-100 characters), plus the same filters as `GET /reports`, `limit` (1-50, default 20).
* **200:** `{ "query": "black wallet", "count": 2, "items": [ { ...Report..., "relevance": 91 }, ... ] }`
* **Errors:** 422 if `q` is missing or too short.

### `GET /reports/{report_id}`
* **Auth:** Bearer. **Purpose:** one report. Hidden reports are returned only to their owner or an admin (others get 404).
* **200:** Report object. **Errors:** 404.

### `PATCH /reports/{report_id}/status`  (CLI `return_item`)
* **Auth:** Bearer; owner or admin.
* **Purpose:** mark a report as returned. Sets `returned_at`, `returned_to`, `resolved_by`, and resolves its active matches.
* **Request:** `{ "status": "returned", "returned_to": "Ravi S" }` (only `returned` is accepted here; claim/approval changes happen in the app).
* **200:** the updated Report object.
* **Errors:** 403; 404; **409 `already_returned`** if it was returned before; 422.

### `POST /events`
* **Auth:** Bearer. **Purpose:** after the app finishes a claim action in Firestore, ask the server to notify the other person. The server re-reads the claim/report from Firestore and checks that the caller really took that action and the state matches, so a client cannot fake notifications. Idempotent.
* **Request:** `{ "type": "claim_submitted", "claim_id": "k3J9..._uidAbc" }`

| `type` | Needs | Caller must be | Notifies |
|---|---|---|---|
| `claim_submitted` | `claim_id` | the claimant | the finder (report owner) |
| `claim_approved` | `claim_id` | report owner or admin | the claimant |
| `claim_rejected` | `claim_id` | report owner or admin | the claimant |
| `claim_completed` | `claim_id` | report owner or admin | the claimant |
| `item_returned` | `report_id` | report owner or admin | owners of its active matches (matches become `resolved`) |

* **200:** `{ "created": 1, "pushed": 1 }`
* **Errors:** 400 unknown type; 403 wrong caller; 404; 409 `state_mismatch` (for example `claim_approved` when the claim is still pending).

### `POST /admin/users/{uid}/role`
* **Auth:** admin. **Purpose:** promote or demote a user (sets the custom claim and mirrors `role` in Firestore).
* **Request:** `{ "role": "admin" }` or `{ "role": "student" }`
* **200:** `{ "uid": "...", "role": "admin", "note": "The user must sign out and in again for the change to apply." }`
* **Errors:** 404 user; 409 if an admin tries to remove their own admin role (prevents lock-out).

### `POST /admin/users/{uid}/disabled`
* **Auth:** admin. **Request:** `{ "disabled": true }`. **200:** `{ "uid": "...", "disabled": true }`. Disabled users cannot sign in again (an already issued token works until it expires, up to one hour).
* **Errors:** 404; 409 when disabling yourself.

### `POST /admin/notifications`
* **Auth:** admin. **Purpose:** send a message to one user or everyone.
* **Request:** `{ "title": "Lost & Found desk", "body": "Open Mon-Fri 9-4", "audience": "all" }` or `{ ..., "audience": "user", "user_id": "uid123" }`
* **200:** `{ "recipients": 412, "pushed": true }` (writes a notification document per user, then one FCM push).
* **Errors:** 422 (`user_id` required when `audience` is `user`); 404 user.

### `POST /admin/rematch`
* **Auth:** admin. **Purpose:** re-run matching for reports whose `match_status` is `pending` or `failed`.
* **Query:** `limit` (1-200, default 50). **200:** `{ "processed": 12, "succeeded": 12, "failed": 0 }`

## 3. Notes for the Flutter side

* The app sets a 15-second timeout on every call and treats any failure of `/match` as "saved, matching pending".
* The app never sends contact details to `/match` or `/events`; the server reads what it needs from Firestore.
* CORS is off by default (native apps do not need it). To use the API from a web build later, list the web origin in `CORS_ORIGINS` in `backend/.env`.
